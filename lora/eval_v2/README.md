# 평가셋 v2 — 깨끗한 평가셋 (NEXT_PLAN 5단계)

학습(KB 스냅샷 65문서) · kb10 과 겹치지 않는 문서로 만든 마지막 확인용 평가셋. **한 번만 쓴다** (NEXT_PLAN 10단계).
정답은 공개하지 않는다 (HF · `deploy/` 에 넣지 않는다). 평가는 서버에서 — 끝나면 `data/gold_v2/` 로 옮긴다.

## 진행

| 단계 | 상태 | 결과 |
|---|---|---|
| 5-1 문서 | 끝 (10-27) | `docs/` — 하나은행 적금 요약 상품설명서 3개 · 출처 `docs/SOURCES.md` |
| 5-2 조문 분할 | 끝 (10-27) | `md/` → `clauses.json` (35조문) · `clauses_all.json` (거르기 전 87) |
| 5-3 정답 1 — 판단 | 끝 (10-27) | `gold/_triage.json` — 규칙 13 · 없음 12 · 표현불가 10. 판정 3명 만장일치 31/35, 갈린 4 는 사용자 결정 (`judges/`) |
| 5-3 정답 2 — 조건식 | 끝 (10-27) | `gold/<조문 id>.json` 35개 — 작성자 3명 비교 일치 21/23, 갈린 2 는 사용자 결정(둘 다 다수). 채택본은 `judges/gold_opus` (최종 답과 23/23 같음) |
| 5-3 검사 | 끝 (10-27) | `tools/check_gold_v2.py gold` → 검증 실패 0/35. «하루 뒤 재검토»는 다중 판정 + 갈린 곳 사용자 확인으로 대신함 (사용자 10-27) |
| 5-4 봉인 · 서버로 | **다음** | 서버 `data/gold_v2/` 로 `gold/` · `clauses.json` 복사 |

**기준선 (⑥ 프로필 256, kb10 과 같은 채점):** 빈 출력 ⑥ 85.5 (35조문) · 정답 rule 조문 61.1 (13) · 정답 빈 100 (22).
정답 rule 13조문 중 빈 출력과 갈리는 것은 9 — 나머지 4는 ⑥ 프로필이 조건을 못 건드린다(만 35세 이하 · 카드 월 30만원 등).

## 정답 만든 기록

- 판단: `judges/judge_{opus,sonnet,fable}.json` → 만장일치 31/35, 둘씩 일치 32~33/35.
- 조건식: `judges/gold_{opus,sonnet,fable}/` → `tools/compare_gold.py` (⑥ 프로필에 나이 30·40 · 기간 24·36개월을 더한 1024 프로필 실행 비교 + 효과 모양 비교) → `judges/compare_gold.json`.
  갈린 2: HNSAL-S2-R06 300만원을 입금 한도로(다수) vs 초과 시 가입 불가 · HNSAL-S2-R09 «계약기간 1/2» 를 기간별 정확히(다수) vs 6개월 고정.
- 표절 검사: 작성자 사이 note 60자 이상 같은 구간 3곳 — 전부 kb10 정답 `KBMY-S2-R11` 의 문구를 각자 옮긴 것(서로 베낀 것 아님).
- **눈가림 한계:** 판정자들이 공유 임시 폴더에 작업 스크립트를 두었다. 1차 판단 때 판정 2명의 스크립트(`judges/triage_scripts/`)가 다른 판정자가 일하는 동안 그 폴더에 있었다 —
  서로 봤다는 증거는 없고 각자 «다른 판정자 출력 열지 말 것»을 지시받았지만, 배제할 수 없다. 조건식 단계에서는 중간에 발견해 옮겼고, 작성자들은 남의 파일을 안 열었다고 답했다.

## 문서 → 조문

- `tools/hana_to_md.py` — PDF → `doc_split.py` 가 읽는 마크다운 (KB 상품설명서 txt 와 같은 꼴).
  1쪽 요약본은 뺀다(2~5쪽과 중복). 본표만 쓰고 칸 안의 작은 표는 버린다(글자는 이미 칸 안에 있음).
  쪽을 넘는 칸은 이어 붙이고, 글자마다 띄운 라벨(«가 입 대 상»)은 붙인다.
- `tools/build_clauses_v2.py` — `doc_split.build` → `doc_split.select` → 분류 rate · eligibility · benefit 만. **kb10 과 같은 거르기.**
- 조문 id 접두어: `HNSAL` 급여하나 월복리 적금 · `HNDRM` (아이) 꿈하나 적금 · `HNWSH` 나의 소원 적금.
- 칸 안의 작은 표(우대항목 표 등)는 두 칸 글자가 줄마다 섞여 나오는 곳이 있다 — 글자 · 숫자는 다 들어 있다. 판단이 애매하면 원본 PDF 를 본다.
- 도구는 `../work/M2-2` (번들에서 복원한 저장소)의 `doc_split.py` 를 쓴다.

## 정답 원칙 (초안 편향 막기)

1. 판단(규칙 / 없음 / 표현불가)은 **독립 판정 3명**(Claude Opus · Sonnet · Fable — 서로의 답 · 사람 답 · 평가 후보 출력을 안 봄)이
   원문 · 카탈로그 · kb10 관례만 보고 하고, 만장일치는 채택, 갈린 것만 **사용자가** 정한다 (사용자 10-27 결정 — 처음 계획인 «사람이 전부 판단»을 바꿈).
   사용자가 먼저 판단한 6조문과 «조건 있음/없음» 수준에서 6/6 일치.
2. 조건식도 같은 방식 — 여러 판정자가 따로 쓰고 갈린 곳만 사용자가 본다. 출처를 정답 파일에 적는다.
3. kb10 정답의 관례(조문 종류별 판단 수)는 `triage_sheet.md` 머리에 참고로만 둔다.
