# personalized_summary v0.3 시스템 프롬프트 평가 (2026-10-14)

평가 방식: 독립 에이전트 4개 병렬 — ① 의사결정표 정합성 ② 내부 일관성·스펙 ③ Qwen2.5-7B 실행성 ④ 테스트 입력 4개로 규칙을 문자 그대로 따라 출력해 보기(추측 지점 48곳 기록). 지적은 원문·표와 대조해 확인한 것만 남김. 실제 모델 실행은 하지 않음.

## 총평
- 정확성 규칙(근거·의미 보존·수치·판정 강도, rule 1~10)은 금소법·감독규정 제13조 취지(혜택+조건 병기, 보장 금지)를 잘 담고 있음.
- 약점은 세 가지: (1) 입력 스키마에 규칙이 요구하는 정보가 없음, (2) "무엇을 앞에 둘지/언제 뺄지"가 모델 판단에 맡겨짐, (3) 7B 모델에게 코드로 할 일까지 맡김.

## 의사결정표 자체에서 먼저 정리할 것
- 프롬프트 IN 23개 중 팀 최종 결정 '확정'은 7개(가입대상, 금리구조, 만기앞당김, 중도해지, 계약해지 방법, 세제, 수수료). '제외' 6개(최고금리, 이벤트·쿠폰, 자동재예치, 자동해지, 관련대출, 명의변경), 보류 4, 원본 확인 필요 5, 확인 필요 1. 세 열(팀 결정 / 생존·죽어 / 프롬프트 IN·제외)의 뜻이 서로 엇갈려 보임 → 열 의미 정의 필요.
- 서비스 상태는 '제외'·'죽어'인데 회의요약은 "중대한 경우만 최초 출력" → 표 안에서 어긋남.
- 우대금리 조건은 '제외'인데 추가질문 '예'이고 "질문 후 개인화"를 강하게 추천 → '제외'를 "조건 목록은 프론트, 적용 판정 문장·질문은 프롬프트"로 나눠 확정 권장.
- 일치율 테스트 정답셋은 '확정' 7개 항목부터 만들 것 (미확정 항목이 정답으로 굳지 않게).

## 7B 실행 권고
- 숫자는 모델이 쓰지 않게: 코드가 "연 2.50%(세전, 2026.10.01 기준)" 같은 표시 문자열을 만들고 모델은 `{F3}` 자리표시만 넣음 → 코드가 검사·치환. FD1·PA1을 코드가 보장.
- 디코딩: `do_sample=False`, `repetition_penalty=1.0` (Qwen 기본 generation_config는 샘플링이라 인자 없이 돌리면 일치율 테스트가 흔들림 — 기본값은 실제 config로 확인 필요).
- 입력 상한: 호출당 fact 12~15개, fact와 판정을 코드가 한 줄로 합쳐 전달, 빈 필드 제거.
- JSON 유지 시 lm-format-enforcer/xgrammar로 형식 강제, 또는 `[S1] 문장` 줄 형식 출력 후 코드가 JSON 조립.
- few-shot 1쌍(가상 상품, 정보/INFO_MISSING/BANK_CONFIRM/예외 4~5문장) 추가.

## system / user 분할
