# Agent 4 — 테스트 설계 + 문자 그대로 실행 시뮬레이션 (personalized_summary v0.3)

- 평가 대상: `in/system_v0.3.txt` (규칙 1~16, 출력 스키마)
- 참고: `in/table_dump.txt` (기획_배치결정표 "프롬프트 IN" 행 중심)
- 테스트 입력 파일: `eval/testcases/T1.json` ~ `T4.json` (프롬프트 [입력] 8개 키만 포함, 추가 키 없음. 함정 목록은 이 문서에만 둠)
- 표기: **[확인]** = 프롬프트·표 원문에서 직접 확인한 사실, **[추측]** = 실행자 입장에서 추정한 것
- 상품·은행명은 모두 가상("가상은행 …")

## 0. 요약 (상위 지적)

| # | 심각도 | 규칙 | 표 행 | 한 줄 요지 |
|---|---|---|---|---|
| 1 | 치명 | 10, 13, 14 | 가입제한·제외조건 | T4: 가입 불가(UNSATISFIED)인데 must_include 가 아니고 purpose 가 금리라서 규칙 13·14를 따르면 **금리·혜택 6문장 뒤 3번째 섹션**에 나오고, 빼 버려도 규칙 위반이 아님. 표의 "가입이 불가능한 조건은 혜택보다 먼저"는 프롬프트에 없음 |
| 2 | 치명 | 10 | 가입제한·제외조건 / 거래·입출금 제한 | UNSATISFIED 템플릿 "입력하신 내용 기준으로는 **적용되지 않습니다**"를 제한 Fact(F401)에 쓰면 "제한이 적용되지 않는다 = 가입 가능"으로 읽힘. state 의 극성(혜택 Fact vs 제한 Fact)이 정의돼 있지 않음 |
| 3 | 높음 | 5, 8, (누락값) | 신규·예치금액 / 납입한도 | value·unit 과 text 가 표기가 다를 때(500000 원 vs "50만원"), user_input 에 단위가 없을 때(0, 200000), value=null 일 때 무엇을 쓰는지 규칙이 없음 → 4케이스 모두 추측 필요. 멘토가 요구한 "누락값 처리 규칙"이 프롬프트에 없음 |
| 4 | 높음 | 5 | 기본금리 / 최고금리 | "고시 금리는 as_of 와 **세전 여부**를 같이 적는다" — Fact 에 세전 정보가 없으면(T2 F207, T4 F402) 규칙 1(입력 밖 사실 금지)과 정면 충돌. 어느 쪽을 어겨도 위반 |
| 5 | 높음 | 3 vs 6 vs 12 | 최고금리 / 우대금리 | 규칙 3 "다른 Fact 의 조건·혜택 연결 금지" vs 규칙 12 dependencies(F101 최고금리 ↔ F103·F104 우대조건은 서로 다른 Fact). 어디까지 묶어도 되는지(같은 문장? 같은 섹션?) 불명. T1 에서는 섹션이 갈려 최고금리가 혼자 첫 문장에 나옴 |
| 6 | 높음 | 10 | 우대금리·이벤트 | SATISFIED = "적용됩니다" 단정. F103 처럼 "가입기간 중 6개월 이상" 미래 조건도 단정하게 됨. 표의 "사용자 적용 여부는 미확정으로 표시"와 어긋남 |
| 7 | 높음 | (입력 스키마) | 최고금리 / 세제 / 수수료면제 | 개인화 결과(예상 적용금리, 세후 결과, 면제 시 절감액)를 넣을 칸이 없음. 규칙 1·5 때문에 계산도 못 함 → 출력이 "조건 재진술 + state 꼬리표"에 그침. 표의 "사용자 예상 적용금리와 공시 최고금리 비교", "세후 결과와 함께 표시"를 구현 불가 |
| 8 | 중간 | 10, 13, 15 | — | INFO_MISSING 문장 "○○을 알려 주시면…"과 questions_for_user 가 같은 내용 → 규칙 13·15 "두 번 쓰지 않는다"와 충돌. missing_fields "그대로 묻는다" = 영문 필드명 노출인지 불명 |

| 10 | 중간 | 7 | 만기앞당김·자동재예치 등 | only_in 이 Fact 단위 필드인데 규칙 7은 "only_in 이 있는 **예외**"라고 씀. exceptions 항목에는 출처가 없음 → 출처 표기 대상이 모호 |
| 11 | 중간 | 출력 스키마 | — | 한 sentence 객체에 판정 Fact 와 일반 Fact 가 섞이거나, 판정 Fact 의 설명문/예외문만 쓸 때 state 를 무엇으로 할지 불명 → 자동 채점의 state 일치 검사가 흔들림 |
| 12 | 중간 | 13 / 표 "제외" 열 | 우대금리 조건·납입한도·연결계좌·만기 후 이율 | 표에서 "제외(프론트 표시)"인 항목도 candidate_facts 로 들어오면 프롬프트에는 거를 규칙이 없음(T1 F103~F105, T2 F207, T3 F305). 2-4 단계 책임인지 프롬프트 책임인지 미정 |

## 1단계 — 테스트 입력 설계

각 케이스는 의사결정표의 "프롬프트 IN" 행을 기준으로 골랐다. 단, 사용자가 지정한 함정 중 일부(우대금리 조건, 월 납입한도, 연결계좌)는 표에서 **"제외"** 로 표시된 행이다 [확인: 표 33·27·47행 마지막 열 "제외"]. 이 점 자체가 지적 12의 근거다.

### T1 — 적금 (`T1.json`) "가상은행 한걸음 자유적금"
| fact | key | 표 행 (IN/제외) | 판정 | 노리는 함정 |
|---|---|---|---|---|
| F101 | 최고금리 4.00% (as_of) | 최고·최종 공시금리 (IN) | 없음 | 최고금리 단독 강조, 세전·as_of |
| F102 | 기본금리 2.50% | 기본금리 (IN) | 없음 | F101 text 와 중복 → 넣을지 |
| F103 | 우대 급여이체 1.00%p, "월 50만원 **이상**" | 우대금리 조건 (제외) | SATISFIED (500000 ≥ 500000, 경계값) | %p, 경계, 미래조건 단정 |
| F104 | 우대 카드 0.50%p, "월 30만원 **초과**" | 우대금리 조건 (제외) | INFO_MISSING [card_spend_monthly] | 혜택 가정 금지 |
| F105 | 월 1만원 이상 50만원 **이하**, value 500000 원 | 납입한도 (제외) | SATISFIED (경계값) | user_input "50만원" vs value 500000 vs text "50만원" |
| F106 | 중도해지이율, value 0.10 / text 는 구간표 | 중도해지 (IN) | 없음 | value 만 인용, 기본금리×30% 계산값 생성 |
| F107 | 가입기간 12개월 | 계약기간 (제외) | 없음 | 선택 여부 |

dependencies `[[F101,F103],[F101,F104]]`, must_include `[F101,F105,F106]`, section_order `["금리","우대금리","납입","해지"]`, purpose "금리가 얼마인지".

## 2단계 — 문자 그대로 실행한 시뮬레이션 출력 + 추측 지점

원칙: 규칙 문장만 따르고, 규칙이 정해 주지 않는 곳은 "가장 문자 그대로인" 선택을 했다. 각 추측은 `G-번호`로 표시.

T1 추측 지점
| G | 규칙 | 선택지 | 내가 고른 것 / 이유 |
|---|---|---|---|
| G1 | 14 | 섹션-Fact 대응 정보 없음. F101 을 "금리"에 둘지 "우대금리"에 둘지 | key 이름으로 "금리". 결과: dependency 짝(F103·F104)과 **다른 섹션**으로 갈라짐 (규칙 14 "관련 정보는 같은 섹션"과도 긴장) |
| G2 | 12 | dependency "같이 말한다" = 같은 문장 / 같은 섹션 / 출력 어딘가 | "출력 어딘가"(가장 느슨한 문자 해석). 같은 문장이면 규칙 3과 충돌할 수 있어 회피 |
| G3 | 3 vs 12 | F101(최고금리)과 F103·F104(우대조건)는 서로 다른 Fact — 묶는 것이 CF3 위반인가 | dependencies 가 명시했으므로 "같이 말하기"는 허용, "한 문장 결합"은 피함 |
| G4 | 13 | F102 기본금리를 넣을지 (F101 text 에 2.50% 포함 → "두 번 쓰지 않는다") | 제외. 결과: 기본금리 고유 as_of 문장이 사라지고 최고금리가 기본금리보다 앞섬 |
| G5 | 5 vs 8 | F105 를 value+unit("500000원"/"500,000원")으로 쓸지 text("50만원")로 쓸지; user_input "50만원" | text 표기 "50만원". 규칙 5 "원 단위를 줄이지 않는다"를 엄격히 읽으면 위반일 수 있음 |
| G6 | 8 | user_input salary_transfer_monthly=500000(단위 없음) 인용 형태 | "500000(500,000원)" — 원래 값 + 환산. "원"을 붙이는 것이 환산인지 불명 |
