# M2-2 — 약관 조문을 실행 가능한 조건식으로

은행 상품설명서의 조문을 기계가 실행할 수 있는 **조건식 JSON** 으로 바꾸고,
그 조건식으로 고객별 최종 적용금리를 계산한다.

```
약관 조문  ──▶  조건식 JSON  ──▶  개별 판별  ──▶  최종 적용금리
           태스크1          태스크2        태스크3
           (LLM)            (순수 코드)     (순수 코드)
```

**LLM 은 태스크 1 에만 쓴다.** 전처리(조문 분할)와 판별(3치 논리 실행기)은
전부 결정론적 코드.

## 지표

형식을 재는 것과 뜻을 재는 것을 갈라 둔다. **섞어 읽으면 안 된다.**

### 형식 (①~⑤, ⑦)

| | 무엇 | 어디 |
|---|---|---|
| ① | JSON 파싱 | `validate.score_record` |
| ② | 스키마 적합 | `schema.SCHEMA` |
| ③ | 카탈로그 준수 | `validate.check_catalog` |
| ④ | quote 가 원문에 있나 | `validate.check_quote` |
| ⑤ | 실행 가능 | `validate.check_executable` |
| ⑦ | 빈 배열 (별도 축) | `report.py` |

### 뜻 (⑥, ⑧~⑫)

| | 무엇 | 어디 |
|---|---|---|
| ⑥ | 실행 결과가 gold 와 같나 (조문 단위) | `scoring.py` |
| ⑧ | UNSUPPORTED 를 얼마나 쓰나 (회피 감시) | `report.unsupported_stats` |
| ⑨ | 생성물의 수가 조문에 있나 | `grounding.py` |
| ⑩ | 조문을 **합쳐** 낸 금리가 gold 와 같나 | `compose.py` |
| ⑪ | 인용문이 그 rule 을 받치나 (**하한**) | `support.py` |
| ⑫ | 빈 배열/UNSUPPORTED/정상 판정이 맞나 | `declare.py` |
| ⑬ | 카탈로그에 없는 개념을 문자열에 담나 | `invent.py` |
| ⑭ | 조건이 붙었는데 언제나 참인가 | `vacuous.py` |

⑭ 는 두 가지를 **갈라 센다.** 프로필 1024개 전부에서 참이라고 다 모델
잘못이 아니다. 카탈로그 정의역을 훑는 문맥 400개(`_free.py`)에서 반례를 찾아
**헛조건**(반례 없음 · 모델의 결함)과 **미가동**(반례 있음 · 프로필의 구멍)을
나눈다. 안 가르면 수치가 여덟 배까지 부푼다.

**⑥ 만으로는 부족하다.** UNSUPPORTED 와 빈 배열을 못 가르고, 조문을 고립시켜
재므로 합성할 때만 드러나는 파괴를 못 본다. 그래서 축을 더 세웠다.


**끊겨도 다시 부르면 이어 돈다.** 라운드는 세 번 끊겼다 — v23(8/46) · v27(11/46) 은
남의 작업이 들어와 OOM, v33(12/46) 은 세션이 초기화됐다. 지금은 같은 명령을 다시
부르면 **남은 부분결과를 거두고 안 된 조문만** 돈다. GPU 가 모자라면 기다린다
(`WAIT=0` 이면 안 기다리고 끝낸다 · `NEED_MIB` 로 문턱을 바꾼다).

**판정선을 3회차 하나로 내지 마라.** 한 프로세스에서 연달아 돌린 회차는 서로 닮는다 —
v38 세 회차만으로는 ⑥ 이 ±1.3p 인데 다른 프로세스의 v37 을 더하면 ±4.1p 다.
잡음을 재려면 **프로세스를 나눠야** 한다 (`NOISE.md` 2026-09-23).

## 라운드 규칙

1. **한 번에 하나만 바꾼다.** 둘을 같이 넣으면 어느 쪽이 먹었는지 못 가린다
2. **가설과 되돌림 선을 결과 전에 적는다.** 숫자를 보고 고르면 무엇이든 설명된다
3. **판정선은 축마다 다르다.** `NOISE.md` 에 실측값이 있다 —
   ⑫ 는 ±2.1p, ⑨ 는 **±23.5p** 다. 하나의 값을 모든 축에 쓰면 안 된다
4. **조문별로 풀기 전에는 군 평균을 처방의 효과로 읽지 않는다**
5. **탈출구를 열기 전에 그것을 세는 축을 먼저 세운다**
6. **표면 지표가 오르면 뜻을 따로 확인한다.** v19 가 표적 이름을 쓰게 만들었고
   표적 조문도 둘 다 맞혔는데, 실물은 `count >= 0` 이라 뜻이 뒤집혀 있었다.
   ⑭ 이 없었으면 성공으로 적을 뻔했다

## 커밋 규칙

**`git add -A` 를 쓰지 않는다.** 경로를 적어 올린다.
한 세션에서 42번 커밋하면서 전부 `-A` 로 쓸어 담은 적이 있다 —
관계없는 변경이 한 커밋에 섞이면 나중에 어느 것이 무엇을 고쳤는지 못 찾는다.

    git add prompt.py schema.py tests/test_prompt.py
    git commit

**한 커밋에 한 가지.** 처방과 채점 수정을 같이 올리지 않는다.
라운드를 돌리기 전에 처방을 커밋하고, 판정을 쓴 뒤 따로 커밋한다.
그래야 결과 파일과 그것을 만든 코드가 이력에서 맞물린다.

**무엇을 추적하나.**

| | 추적 | 왜 |
|---|---|---|
| `*.py` · `tests/` · `*.md` | 예 | |
| `data/gold/` · `data/corpus.json` | 예 | 정답과 입력이다 |
| `results/*.json` | **예** | 라운드마다 GPU 한 시간 안팎(46조문 1회차 33~65분). `raw_first`/`raw_last` 에 모델 원문이 있어 **채점기를 고칠 때마다 전부 다시 잰다** |
| `logs/` | 아니오 | 진행 표시가 대부분. 실행 시간만 `EXPERIMENTS.md` 에 옮겼다 |
| `__pycache__` · `.pytest_cache` | 아니오 | |

결과 파일이 5MB 라 저장소가 무겁지만, 이것 없이는 과거 라운드를 다시 못 잰다.
이 세션에서만 축 셋(⑨ 분모 · ⑭ 가르기 · ⑥ 기준선)을 고치고
전 라운드를 다시 채점했다.

  **순위를 "언급한 조문 수" 로 매기면 안 된다** — 걸림돌은 묶여서 온다.
